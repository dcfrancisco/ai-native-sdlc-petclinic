# Running the Labs

The practice has three connected surfaces:

- `journey/` is the primary ten-stage teaching path;
- `labs/reader-project/transfer-workbook.md` guides transfer to software chosen by the reader;
- `labs/controlled-experiment/` contains an optional experiment protocol and is not required for the core journey.

Each lab has three movements:

1. Perform the chapter practice on PetClinic.
2. Compare with the reference artifact.
3. Produce the equivalent artifact for your own software.

Do not begin by copying the reference answer. The educational value comes from making the decision and then reviewing the result.

## Required tools

- Java and Maven wrapper for build evidence;
- browser for human functional checks;
- Docker for PostgreSQL, MySQL, and packaged-runtime evidence;
- IDE or terminal for inspection and implementation;
- AI assistant capable of receiving the structured instruction.

## Lab evidence

Store your commands, concise results, observations, and limitations. Do not commit credentials, dependency caches, unrestricted logs, or database volumes.

## Your project

Your software does not need to use Java, Spring, Maven, or Docker. Preserve the engineering function:

- identify authoritative context;
- frame the outcome;
- make architecture decisions;
- decompose work;
- bound the AI contribution;
- verify with independent evidence;
- govern consequential decisions;
- operate and learn.
