# Adoption Plan

**Chapter:** 16
**Status:** Reference pilot

## Hypothesis

Structured context, bounded roles, contribution contracts, and explicit evidence will reduce preventable scope and verification defects for work similar to the reminder capability.

## Pilot boundary

- one team;
- one bounded application capability;
- no production provider;
- human approval at requirements, architecture, implementation, security, and release gates;
- existing IDE, terminal, Maven, browser, and Docker tools.

## Entry criteria

- authoritative context is available;
- work can be bounded;
- reviewers have capacity;
- tool permissions are understood;
- acceptance evidence can be produced.

## Stop criteria

- sensitive context cannot be controlled;
- baseline evidence is unreliable;
- review load exceeds team capacity;
- AI changes repeatedly cross approved boundaries;
- consequential decisions lack owners.

## Review cadence

Review findings, rework, evidence gaps, incidents, and team feedback after each work package. Expand only when the observed benefits and risks justify expansion.
